The Library Model

How knowledge is addressed across the memory graph and the filesystem. The graph is the card catalog; the filesystem is the stacks. A neuron is a catalog card — a thin pointer with a summary — not the book itself. You walk from a question to the exact paragraph in four narrowing hops, tier by tier.

1 · Four Tiers 2 · Card vs Book 3 · Two Libraries 4 · No Orphans Worked Walk Legend

1Four tiers — catalog → section → shelf → book

A library gets you from "I have a question" to "the paragraph I need" by narrowing at each step. Our system mirrors it exactly. You never start at the book and hope — you start at the catalog and walk down.

The narrowing. Each hop is smaller than the last. The catalog (cheap, ~150–250 tokens) is auto-injected into every session by the SessionStart hook; books are pulled on demand. Blind keyword search teleports past tiers 1–3 and lands on the wrong shelf — always route by mission first.

2The core rule — a neuron is a catalog card, not the book

The graph indexes; the filesystem holds the depth. A neuron stays thin: a 2–4 word title, a one- or two-line summary, edges, tags, and — when depth lives in a file — a pointer to that file's path. You don't photocopy the book onto the index card.

Decide by depth, at write time. An atomic fact / rule / contact / decision lives fully in the neuron (e.g. "SAM expires 2026-11-19") — no file. A long, structured, or evolving document lives in a file; the neuron becomes a thin card that indexes it. Both directions must connect — no orphans on either side.

# the card — a thin neuron that points to the book memory neuron add "Network Intrusion Prototype — AI-driven NIDS prototype. \ Full writeup: docs/capabilities/network-intrusion-prototype.md" \ --parent <Capabilities hub> --tags capability,prototype,active memory attr add <id> path docs/capabilities/network-intrusion-prototype.md
Why split catalog from stacks? Token cost — push the cheap index every session, pull the heavy book on demand. Search quality — a graph of thin, well-edged cards routes far better than one stuffed with full documents. Right tool per tier — the graph routes and relates; the filesystem holds and versions depth. The neuron is the seam.

3Two libraries — central & regional (store federation)

The tiers operate within one library. But there are two kinds, federated: one CENTRAL reference library (GLOBAL) and many REGIONAL branches (per-project LOCAL). A branch is defined by the store — the nearest .memory/ found by ancestor-walk — not by a repo.

Federation is upward by default. ▲ automatic Standing in a regional branch, a query sees regional then central — regional results first, local wins on conflict. ▼ deliberate Central points down only via the Branch Registry hub (one synopsis card per branch) and cross-store edges, so something working from central can discover which regions exist and resolve <fingerprint>:id to read across. Regions can't see each other.

Self-enforcing. A branch-sync step in the SessionStart hook resolves the active store; if it's a LOCAL branch, it upserts that branch's synopsis card under the registry hub (keyed by a branch-<fingerprint> tag). The skeleton is mechanical and cheap — guaranteed fresh regardless of agent compliance.

4No orphans — on both sides

The graph forbids orphan neurons; the filesystem mirror forbids orphan docs. Every neuron is child_of a hub; every doc is listed in a folder index, linked up to the repo root. A doc reachable from the graph but in an unindexed folder is half-orphaned — both paths must hold.

Both directions connect. Card → book: the neuron names the file path (body, or a path attr). Book → shelf: the file sits in a folder whose INDEX.md lists it, and that index links up to the repo root. Code, tests, and generated artifacts are the exception — captured by a one-line role per directory, not file-by-file.

End-to-end walk — a real example

Catalog → section → shelf → card → book, using actual hubs in this system.

# TIER 1 — catalog: the deterministic entry point (auto-injected each session) $ memory neuron list --tag hub FEDERAL CONTRACTING · METHODOLOGY / R&D · PEOPLE CONVERGENT CAPABILITIES · REGIONAL BRANCHES · MEMORY CONVENTION · RUNWAY TRACKER # TIER 2 — section: route by mission to the hub (cite by NAME, not ID) $ memory neuron search "CONVERGENT CAPABILITIES" # TIER 3 — shelf: its children (in-graph) — or the docs/capabilities/ folder on disk $ memory neuron list --parent <Capabilities hub> → card: "Network Intrusion Prototype" # TIER 4 — the book: the file the card points to $ open docs/capabilities/network-intrusion-prototype.md

Reachable two ways — catalog → Capabilities hub → card → file, and browsing the stacks → README → capabilities INDEX.md → file. No orphan on either side.
